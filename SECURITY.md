# Security Documentation

This document outlines the security measures implemented in the AI Learning Management Platform to protect user data, secure API endpoints, and ensure safe database interactions.

## 1. Authentication (JWT)
- **Mechanism**: The platform uses custom JWT (JSON Web Token) authentication managed by FastAPI.
- **Passwords**: User passwords are securely hashed using bcrypt before being stored in the database.
- **Tokens**: The `SECRET_KEY` environment variable is used to sign JWTs. Tokens have a finite lifespan defined by `ACCESS_TOKEN_EXPIRE_MINUTES`.
- **Protected Routes**: FastAPI's `Depends(get_current_user)` dependency is used to secure private endpoints.

## 2. Authorization
- The backend relies on Role-Based Access Control (RBAC). The `role` column in the `users` table dictates permissions (e.g., Student, Teacher, Admin).
- API routes explicitly check `current_user.role` to restrict administrative actions.

## 3. Database Security
- **SQL Injection**: We use SQLAlchemy ORM exclusively. The ORM inherently sanitizes inputs and uses parameterized queries, neutralizing SQL injection vulnerabilities.
- **Row Level Security (RLS)**: RLS is enabled on the Supabase PostgreSQL database. While the backend accesses the DB via a service role (bypassing RLS), RLS ensures that any rogue access via the Supabase Data API or client libraries is strictly locked down.

## 4. Environment Variables
- **Secrets**: No secrets (API keys, database URLs) are hardcoded. Everything is loaded dynamically via `backend/app/core/config.py` from `.env` or system environment variables.
- **Supabase Keys**: The frontend does not use the Supabase Anon Key. All database and storage interactions run securely through the FastAPI backend, hiding Supabase configurations from end users.

## 5. Storage Security
- Private files uploaded to Supabase Storage are accessed via Short-lived Signed URLs generated by the backend.
- The `StorageService` handles generating these signed URLs, preventing unauthorized public access to sensitive course materials or user data.
